# Exp1 实验笔记更新规范

## 目标文件

```
czy/exp1/exp1.md
```

**分工**：

| skill | 职责 |
| --- | --- |
| **lab-notebook（本 skill）** | 编号、索引表、实验章节结构、写回结论 |
| `isaac-diag-eval`（可选） | 跑 `eval_isaac_diag.py`，产出 E1~E8 诊断数值（需 CSV，无 CSV 时用训练日志数据） |

新建/更新实验必须遵循本 skill 的章节模板。

## 一、实验编号规则

### 1.1 格式（阶段 + 阶段内尝试）

```
exp{阶段}.{尝试}    或    exp{阶段}（阶段首次尝试可省略 .1）
```

- **阶段（主编号 `exp{n}`）**：对应一个**阶段目标**（如 reward≥25, ep_len≥900）。阶段目标未达成前，所有尝试都归入同一阶段。
- **尝试（子编号 `.{m}`）**：阶段内的第 m 次尝试。`exp1` 不达标 → 微调优化 → `exp1.1`；仍不达标 → `exp1.2`…
- **阶段晋级**：只有某次尝试**达标**后，才进入下一阶段 `exp{n+1}`。

| 示例 | 含义 | 何时使用 |
| --- | --- | --- |
| `exp0` | 基线（首个实验） | 独立保留，不归入任何阶段 |
| `exp1` | 阶段1 首次尝试 | 设定阶段目标后开训 |
| `exp1.1` | 阶段1 第2次尝试（微调1） | exp1 未达标，微调后重训 |
| `exp1.2` | 阶段1 第3次尝试（微调2） | exp1.1 仍未达标，继续微调 |
| `exp2` | 阶段2 首次尝试 | exp1.x 已达标，进入新阶段（新目标） |

**规则**：
- 编号不可变：失败尝试保留编号，索引表状态标「失败」，不删除不跳号
- `exp0` 是特殊基线，不参与阶段编号

### 1.2 微调（新建子编号 `.{m}`，不晋级阶段）

`exp{n}` **未达标**时，修改参数后重训 → 新建 `exp{n}.{m}`（m 递增）：

- 微调范围：仅改 1~3 项奖励权重、小参数、小幅修正
- 微调继承父实验的修改编号（见 §3）

### 1.3 晋级（新建主编号 `exp{n+1}`）

满足**任意一条**时，阶段晋级：

- `exp{n}` 或其微调 `exp{n}.{m}` **达标阶段目标** → 新阶段 `exp{n+1}` 设新目标
- 跨 ≥2 个模块的大改（新增/删除奖励、改 IK 逻辑、改 URDF）→ 即使未达标也晋级
- 切换训练任务（如 Flat → Rough）→ 晋级并在 §5 标注 task 变化

### 1.4 原地更新（不改编号）

满足**任意一条**时，不新建编号，直接更新现有实验的 §7：

- 训练中途观察日志，仅做趋势分析（未训完）
- 训练完成后补充结果数据
- 发现记录有误，修正数值

## 二、索引表更新规则

文件顶部 `## 实验索引` 表格，**每新建实验必须先加一行**：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 编号 | ✅ | 如 `exp2` |
| 日期 | ✅ | `YYYY-MM-DD` |
| 摘要 | ✅ | 一句话：改了什么、结果判定 |
| 状态 | ✅ | 见下表 |
| Task ID | ✅ | GM 任务 ID，如 `TASK_20260730_200` |
| GM账号 | ✅ | 训练使用的 GM 账号邮箱，如 `yijed24226@barumart.com` |
| checkpoint | ✅ | 最终模型文件名，如 `model_3000.pt` |

**状态枚举**：

| 状态 | 何时使用 |
| --- | --- |
| 待训练 | 方案已写，未开训 |
| 训练中 / 续训中 | 正在跑 |
| 已测试 | 训练完成，结论已写 |
| 失败 | 未达验收目标，保留教训 |
| 已废弃 | 方向否定，不再续做 |

## 三、修改内容编号规则

§3「修改内容」内部用**修改一、修改二...** 编号：

- **微调（`exp{n}.{m}`）**：修改编号**继承**父实验。如 exp1 有「修改一、二」，exp1.1 接「修改三」。
- **晋级（`exp{n+1}`）**：修改编号**重置**，从「修改一」重新开始。

```markdown
## 实验 exp1（阶段1 首次尝试）
### 修改一：…
### 修改二：…

## 实验 exp1.1（阶段1 微调1，继承）
### 修改三：…    ← 接续 exp1

## 实验 exp2（阶段2，重置）
### 修改一：…    ← 重新从「修改一」开始
```

## 五、Agent 工作流

### 5.1 新建实验

1. **判断编号**：
   - 上一实验**达标**（或跨模块大改/换任务）→ 晋级 `exp{n+1}`（修改编号重置）
   - 上一实验**未达标**且仅小改 → 微调 `exp{n}.{m}`（修改编号继承父实验）
2. 在索引表**末尾**追加一行
3. 在文件**末尾**追加完整实验章节（§1~§7，§7 占位「待训练完成后补充。」）
4. §1 必须引用上一实验 §7 的**具体数值**，禁止只写「效果不好」

### 5.2 训练完成后更新结果

1. 用 `gm task data get` 拉训练曲线关键点数据
2. 将 Mean reward、Episode length、各奖励项最终值填入 **§7**
3. 写分级结论（✅达标 / ⚠️部分达标 / ❌未达标）
4. 更新索引表：状态 → `已测试` 或 `失败`；摘要补关键判定

### 5.3 训练中途更新（不改编号）

1. 不新建实验，直接在现有 §7 追加「训练进度趋势」小节
2. 索引表状态保持「训练中」

### 5.4 禁止事项

- ❌ 不编造未拉取的数据
- ❌ 不删除失败实验记录
- ❌ 不跳号（exp2 之后是 exp3，不要直接 exp5）
- ❌ 结论禁止笼统「还行」，必须分级 + 量化

## 六、快速决策表

| 场景 | 编号 | 动作 |
| --- | --- | --- |
| 基线 | `exp0` | §1 写「无上一轮」 |
| 阶段1 首次尝试 | `exp1` | 设阶段目标开训 |
| 未达标，小改重训 | `exp1.1` | 微调，§3 修改编号继承 exp1 |
| 达标后开新目标 | `exp2` | 晋级，§3 修改编号重置 |
| 训练失败但教训明确 | 原编号 | 更新 §7 + 状态「失败」 |
| 训练中途看日志 | 原编号 | §7 追加趋势，不改编号 |
| 跨模块大改（未达标也晋级） | `exp{n+1}` | 重置修改编号 |
| 切换任务（Flat→Rough） | `exp{n+1}` | 晋级，§5 标注 task 变化 |

## 七、注意事项

1. **§1 教训必须可量化**：至少 2 个来自训练日志或 isaac_diag 的数
2. **失败同样完整记录 §7**：失败原因写在根因分析
3. **索引表与正文状态一致**
4. **结论分级**：✅达标 / ⚠️部分达标 / ❌未达标，禁止笼统表述
5. **GM 数据获取**：用 `gm task data get --task-id ... --data-key "Train/mean_reward"` 拉曲线

## 八、数据归档规范

`czy/data/{实验编号}/` 下每个实验子文件夹**只允许存放三个文件**：

| 文件 | 说明 |
| --- | --- |
| `model_{N}.pt` | 训练结果模型 checkpoint |
| `play_output.mp4` | play 回放视频 |
| `isaac_diag.csv` | play 回放诊断 CSV |

禁止在该目录存放 `model_isaac_csv.pt`、分析 PNG、日志等额外文件。分析图/临时打包文件如需保留，放 `czy/analysis/` 或项目外目录。
