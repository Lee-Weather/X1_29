### 8. `isaac_diag.csv` 诊断结果

本次分析文件：`czy/data/exp0/isaac_diag.csv`，共 2000 帧、20.00 s、47 列。回放中出现两次明显终止/reset：

- 第一次约发生在 `3.45 s`：前一帧 base height 为 `0.1085 m`，终止前 `base_vel_x=-2.954 m/s`、`base_vel_y=2.132 m/s`。
- 第二次约发生在 `12.39 s`：终止前 `base_vel_y=2.302 m/s`，base height 从 `0.518 m` 降至 `0.415 m`。

#### 8.1 速度跟踪

在 `command_x > 0.3` 且机器人尚未明显倒地的样本中：

- 指令速度均值约为 `0.663 m/s`；
- 实际 `base_vel_x` 均值约为 `-0.039 m/s`；
- 速度误差 RMSE 约为 `0.741 m/s`；
- 指令与实际速度相关性约为 `-0.02`。

这表明策略没有实现前向速度跟踪，主要表现为原地站立、拖步或向后滑动。

#### 8.2 足端步态

在稳定片段 `4–11 s` 中，左脚高度超过 `0.06 m` 的比例约为 `9%`，右脚为 `0%`；左右脚接触比例约为 `93%` 和 `100%`。右脚几乎始终贴地，未形成有效的左右交替摆腿。当前策略更接近双脚着地保持，而不是参考轨迹要求的稳态行走。

#### 8.3 关节限位与力矩

- 左踝俯仰关节超出 URDF 限位约 `10.75%` 的采样点；
- 右踝俯仰关节超出 URDF 限位约 `7.60%` 的采样点；
- 左髋横滚、左髋偏航存在少量触限；
- 踝关节记录力矩峰值约为 `27.4` 和 `24.0`，高于 MJCF 中约 `18` 的踝关节执行器限值。

若 CSV 记录的是限幅前请求力矩，说明踝关节控制压力过大；若记录的是限幅后力矩，则需进一步核对诊断记录位置。

#### 8.4 诊断结论

`exp0` 的训练和回放基础链路成功，但实验目标未达成，故索引状态改为“失败”。主要问题按优先级为：

1. 参考轨迹没有转化为真实前向行走；
2. 双脚长期接触，右脚基本不抬起；
3. 前向、横向速度在失稳前快速发散；
4. 踝关节存在限位和力矩压力；
5. 原 CSV 缺少 `command_y`、`command_yaw`、动作、参考关节、阶段和 reset 标志，无法精确判断终止原因。

下一次回放将由 `humanoid/scripts/play_gm.py` 额外记录动作前状态、`command_x/y/yaw`、动作值、参考关节/根部状态、阶段、参考帧、`done` 和 `time_out`，并保留 reset 前的终止状态，避免 reset 后的初始状态覆盖摔倒现场。

## 实验 exp0.2：激励结构修复（精简版方案）

### 1. 实验目的

修复 exp0.1 暴露的激励结构缺陷，使策略从"站稳混满时长"转向"沿参考轨迹真实前进"：产生前向位移、左右交替单脚摆动、消除高频偏航振荡，同时保持 exp0.1 已达标项（存活 5.67 s、base height ≥ 0.50 m、横向速度 RMSE ≤ 0.15 m/s）。

### 2. 上一实验结果与教训

- exp0.1 根因判断（§12.5）：策略学会保持高度和阶段计时，但未学会前进；靠髋/踝大残差和偏航振荡维持站立；timeout 被当作完成信号，存活与姿态奖励对"无前进、无交替摆腿"无约束。
- 关键教训：失败模式是**激励问题而非信息问题**——actor 已观测完整参考轨迹（ref 关节位置/速度、ref 根部状态、阶段 one-hot），关节 RMSE 0.169 rad 说明"看到了也跟了"，但 base 不前进。两个机制性原因：
  1. 走完序列 = timeout = 成功，学步态无额外收益；
  2. `exp(-err²/σ²)` 形奖励的梯度死区：`trajectory_root_pos` 的 σ=0.25 m，落后参考 0.5 m 以上梯度趋零，原地站立"无痛"。
- 方案取舍：曾拟定 8 个新奖励 + 观测 +8 维（含 FK 脚端高度）的完整方案；代码核对后判定过度设计，降级为精简版。冗余依据：
  - `_get_phase` 的 sin/cos 已在 `command_input` 中（WALK 周期相位），新增相位观测重复；
  - `commands[:, :3]` 每步写入机体系参考速度，`ref_forward_dir` 观测重复；
  - 父类 `_reward_action_smoothness` 已含一阶差分 + 二阶差分 + `0.05·Σ|a|`，action_rate/action_magnitude 新罚项重复；
  - 父类 `_reward_foot_slip` 已实现（当前 scale=0 禁用），重新启用即可；
  - `ref_foot_z` 需全新 6-DOF FK（URDF 关节 origin 全带非平凡 RPY），是全方案最大 bug 风险点，且摆动信息已隐含在 ref 关节位置中，推迟。

### 3. 修改内容（6 项）

#### 修改一：奖励结构精简重构

### 6. 风险与推迟项

| 风险 | 应对 |
|---|---|
| `only_positive_rewards=False` 激活全部既有罚项，负奖励过深导致学习崩溃 | 监控 iter 500 时 mean_reward；若 < -100，将 foot_slip 减半至 -0.25 |
| single_support 相位无关形式可能学出"跳步"而非参考步态 | 权重仅 0.8，关节跟踪 3.0 主导时序；若摆腿与参考反相，下轮改用参考对齐版本 |
| forward_progress 在站立段退化为"站着不动=满分" | 预期行为（站立段参考速度为 0，奖励静止，语义正确） |
| 4000 轮仍不达标 | 若核心 4 项中 ≥ 2 项达成，记录半成功，exp0.3 针对性补强而非全重来 |

推迟项与升级触发条件（归入 exp0.3 候选，逐项独立归因）：

| 推迟项 | 升级触发 |
|---|---|
| FK ref_foot_z + foot_contact 观测 | 本轮摆腿仍为 0 或摆动高度 < 1 cm |
| 残差收缩 + curriculum | 本轮关节 RMSE 恶化 > 0.25 rad |
| 独立偏航振荡罚项 | root_ang_vel 加权 1.0 后 w_z 过零仍 > 5 Hz |
| 参考对齐 single_support（指定摆动脚） | 本轮出现反相摆腿 |
